# Henes T870 급발진 이슈 정리

작성일: 2026-03-10  
대상 파일: `RMM_Henes_V1.2.ino`

## 1) 배경

- 본 차량은 인수 시점 부터 이 폴더에 있는 아두이노 코드가 업로드되어 그대로 사용해온 것으로 보인다.
## 2) 증상 요약

- 급발진 현상은 **Auto 모드가 아니라 Manual 모드에서만** 발생했다.
- Auto 모드는 아직 실제 주행 테스트를 수행하지 못했다.
- 급발진이 시작되면 차량을 사람이 들어 올린 뒤에도 바퀴가 매우 빠르게 지속 회전하는 상황이 관찰됐다.

## 3) 재현 조건 및 관찰 결과

- T870 매뉴얼상 적정 하중은 30kg으로 확인했다.
- 하지만 실제로는 4개 바퀴에 약 15~20kg 수준 하중이 걸려도 급발진이 발생했다.
- 반대로, 바퀴가 아닌 차량 하단 프레임을 지지한 상태에서 하중을 준 경우에는 같은 현상이 발생하지 않았다.
- 종합하면 **바퀴 접지/구동계에 하중이 걸리는 조건에서만** 문제가 유의미하게 나타났다.
- 하중이 크지 않을 때는 정상 동작했다.

## 4) 전원/안전 구조 관련 현재 확인 사항

- 전원은 아두이노 보드, wheel 보드, drive 보드에 병렬 연결되어 있다.
- e-stop은 wheel 보드와 drive 보드에 **명령 신호만 전달**하며, 전원을 직접 차단하는 구조는 아니다.
- 실제 급발진 시 e-stop 명령이 기대대로 동작하지 않는 상황이 관찰됐다.

## 5) 현재 가설

- 현상 패턴상, 순수한 상위 로직(명령 생성) 문제보다 하위 제어단(모터 드라이버/피드백/전원 품질/배선/접지)에서 문제가 발생할 가능성이 높다.
- 특히 하중 조건에서 증상이 강화되는 점은 전압강하, 노이즈, 접지 바운스, 피드백 왜곡 가능성과 일치한다.
- 코드 레벨에서도 특정 조건에서 출력이 고착될 수 있는 구조가 있어, 하위 노이즈와 결합 시 지속 급발진으로 이어질 수 있다.

## 6) 코드 관점 참고 포인트 (현상 이해용)

- 속도 출력이 누적형으로 계산되는 부분:
  - `Sp_PWM_F_R = Sp_PWM_F_R + Sp_PWMval_R` (`RMM_Henes_V1.2.ino` line 693)
- 속도 피드백으로 사용되는 값:
  - `Sp_encoder_val_R = E_R` (`RMM_Henes_V1.2.ino` line 659)
- `E_R` 갱신 위치:
  - 루프 후반 `E_R = EncoderCount_R - EncoderCount_prev_R` (`RMM_Henes_V1.2.ino` line 331)
- RC 읽기 시 인터럽트 비활성:
  - `noInterrupts(); pulseIn(...); interrupts();` (`RMM_Henes_V1.2.ino` lines 342~381)

위 요소는 하중/노이즈 상황에서 피드백 저하가 겹치면 출력이 빠르게 커지고 쉽게 내려오지 않는 조건을 만들 수 있다.

## 7) 즉시 점검 항목

- 하중 상태에서 Arduino 5V 및 수신기 5V 전압 강하/리플 측정
- 하중 상태에서 RC PWM 입력 폭(특히 throttle 채널) 변형 여부 측정
- 하중 상태에서 엔코더 A/B 파형 누락, 바운스, 레벨 불안정 여부 측정
- e-stop 하드웨어 차단 체계(전원 차단형) 적용 가능성 검토

## 8) 결론

- 현재까지의 증거는 "코드만의 단독 문제"보다는 "하중 조건에서 하위 제어단/전원/피드백 품질 문제 + 코드의 출력 고착 가능 구조"가 결합된 이슈에 가깝다.
- 따라서 코드 분석과 동시에 전원/배선/드라이버/센서 신호 무결성 점검을 병행해야 한다.
