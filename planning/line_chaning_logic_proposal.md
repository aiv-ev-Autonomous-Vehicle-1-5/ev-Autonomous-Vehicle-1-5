# line-chaining logic 구현
- 기존 planning_mr_ver의 좌/우 차선의 라바콘들의 간격이 듬성듬성하여 그 틈 사이로 자기장 틈이 생겨 경로가 바깥쪽으로 튀어버리는 경우가 존재하므로 좌/우 차선(라바콘)을 각각 독립적으로 nearest-neighbor chaining 변형하여 적용한다.
## seed 알고리즘
- 좌/우 차선을 묶을 때는 차선 point와 라바콘 point를 같은 corridor로 보고 연쇄적으로 연결한다. 다만, 각각의 정체성은 유지하되 좌/우 polygon 연결관계를 확정지을 때만 같다고 보며 polygon을 형성한다. costmap에는 라바콘/차선으로 분리되어 올라간다. 
- 왼쪽차선 seed는 ego를 기준으로 y>0이고 ego와 가장 가까운 점
- 오른쪽 차선 seed는 ego를 기준으로 y<0이고 ego와 가장 가까운 점으로 뽑는다
### chaining 알고리즘
- chaining의 맨 처음 seed를 선정했을 때는 직전 포인트가 없기때문에 직전 포인트들과 현재 포인트를 포함한 n개(>=2개 ~ <=7)라고 하자 그 n개 점을 linear regression하여 방향벡터를 구한다. 탐색반지름은 r(parameter로 선언하여 정할 수 있음. default=1) 현재 포인트에서 위에서 구한 방향벡터 방향 기준으로 전방 deg(parameter 선언. default=2*ㅠ/4)안에서 다음 point를 찾는다. 후보들을 못찾으면 찾을때까지 or 모든 포인트들을 탐색할때까지 탐색반경을 0.5m씩 키우며 다시 탐색한다. 이 때 라바콘 후보들이 차선 후보들보다 무조건 우선이다. 탐색반경안에 라바콘과 차선 포인트들이 같이 있으면 라바콘만 후보로 올리고 점수를 준다.위에서 만든 방향벡터를 연장한 직선 기준으로 왼쪽차선을 chaining할 때는 오른쪽으로 멀리 떨어져 있을 수록 점수를 높게 주고. 오른쪽 차선일때는 직전 만든 방향벡터를 연장한 직선 기준으로 왼쪽으로 멀리 떨어져 있을 수록 점수를 높게 준다.
- 이 과정에서 탐색된 모든 후보들을 방문할때까지 이 과정을 반복한다.
- 이렇게 하면 최종적으로 좌/우 독립적인 chain이 나온다.
- 두 폴리라인의 교차검증은 하지 않는다.
- 이제 각 차선을 각각 resampling한다 resampling방법은 다음과 같다.resampling할 때 차선-차선, 차선-라바콘 포인트 사이는 차선으로 resampling하고 라바콘-라바콘 사이만 라바콘으로 resampling한다. 







- 좌/우 차선 chain이 만들어졌으면 각각 resampling하여 간격을 일정하게 만든 뒤, planning_mr_ver의 핵심알고리즘을 적용한다.
