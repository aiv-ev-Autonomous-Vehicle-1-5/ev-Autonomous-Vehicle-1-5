# chaining logic 전면 수정

## chaining logic
1. seed 찾기
    * ego pose - position(0,0), heading(1,0) 으로 고정. 따라서 t_end든 무슨 접선을 이용해서 seed를 찾을 수 없고 할 필요도 없음.
    * 간단하게 로컬 좌표계에서 맨 왼쪽 아래 지점에서 원형의 탐색범위를 키워나가며 첫번째로 보이는 corridor(차선 or 라바콘, 라바콘 우선)를 seed로 잡음. 오른쪽 차선도 마찬가지.
2. 핵심 chaining 로직
    * seed를 뽑았을 때 그 corridor가 현재 프레임에서 보이는 corridor의 실제 main line의 seed가 아닐 수 있음.
    * (예시) ㅏ|자 모양 corridor를 상상해보자 왼쪽차선에 툭 튀어나온 곳을 ego가 비스듬히 지나갈 때, 현재 seed탐색 로직으로는 ㅏ의 맨 아래(첫번째 = 실제 잡아야 하는 seed) 포인트를 시드로 잡지 않고 중간에 툭 튀어나온 포인트를 seed로 잡을 수 있음. 이런경우에도 왼쪽 차선을 chaining으로 탐색하고 왼쪽차선 chain을 형성하려면 현재 chaining 로직도 변경해야할 필요가 있다고 생각함. 전부 폐기하고 완전히 다른 방식을 적용 안해도 될 것 같다고 생각함. 
     * 현재로직 핵심 알고리즘은 다음과 같음 : seed가 확정되면 seed를 중심으로 반지름r의 원형 탐색범위 안에 다음 왼쪽 차선 point로 확정지을 포인트들의 후보를 탐색하고 일정한 조건들을 만족할수록 높은 점수를 부여함. 제일 높은 score를 가진 포인트를 다음 포인트로 확정하고 visited 표시, 이제 원형 탐색범위의 중심을 그 포인트로 이동하여 같은 방식으로 visited되지 않은 포인트들을 탐색하며 같은 직전과 같은 과정을 모든 왼쪽 차선 point를 찾을 때까지 chaining하며 반복함. 이 때 완성도를 높히기위하여 이미 확정된 직전포인트와 현재 탐색 원점 포인트를 잇는 방향벡터를 중심으로 탐색반경을 제한하여 오른쪽 corridor에 포함돼야할 포인트를 왼쪽차선이 확정짓는것을 방지할 수 있음. 
     * 그런데 위 방법으로하면 (예시)케이스인 경우 모든 왼쪽차선을 chaining하기에 역부족이라고 생각함. 그래서 탐색 방법을 보완하는게 좋을것 같음 내가 생각한 보완 로직은 아래와 같음.
     * 일단 point를 확정지으면 그 포인트로 이동함. 직전포인트에서 현재 원형 탐색 중심 포인트로의 방향벡터를 중심으로 좌/우 합 60도를 탐색반경으로 설정하고 다음 포인트 후보들을 찾음. 이 때 찾은 후보들 모두에 높은 점수를 부여함 그리고 다시한번 탐색을 다시 한 번 함. 현재 포인트 주변 360도 모든 점들을 후보로 삼아 (당연히 visited 포인트는 제외) scoring을 계산함. 이 새로 탐색된 후보들 모두에게 첫번째 탐색반경에서 부여한 점수보다 낮은 점수를 부여함. 이렇게 두 번의 탐색에서 선별된 후보들에 이제 필터링 로직을 적용하여 나머지 점수들을 공통 기준으로 적용.
     * 그런데 위 방법을 떠오릴다가 생각한건데 기존 방법은 dfs랑 비슷하고 새롭게 떠올린 방법은 bfs랑 비슷하잖아. 그러면 bfs를 사용할 수 없을까 하는 생각이 듦.
    아무튼 요약하자면. 기존 방법으로는 seed를 차선의 중간점으로 하면 전체 차선을 chaining하기 힘들다고 생각했고 새로운 방식으로는 같은 케이스에 대해 전체 차선을 chaining하기 쉽다고 생각함.
    
    내 아이디어를 검토하고 평가해줘. 개선사항이나 더 좋은 방안이 있다면 제시.
